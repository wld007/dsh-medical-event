# 病历事件还原 · 交接说明

> 给新会话的起点。先读 `docs/family.md`（插件家族与共同约定），再读本文件，再读 `docs/event-package.md`（交付格式草案）。
> 整理于 2026-11-11。尚未写代码；`design/` 里有 4 张效果图。

## 1. 一句话

把一位患者的病历变成**可计算的事件**：每处提及单独记一条、挂两个时间（写成时间、所说发生时间）、标类型、把同一件事归并成事件、登记记录之间的冲突。只照抄原文、不推断、不补全。

对应原八道工序的 **工序 1–4**。工序 5 以后属于 `dsh-medical-ontology`。

## 2. 输入与输出

- **输入**：区域平台导出 JSON（就诊、诊断、检验、检查、病历记录、手术、费用、人口信息，按月分文件），通常是 `dsh-medical-anonymizer` 的交付目录，也可以是未匿名化的原始导出（界面要提示）。按病人分组，一人一组。
- **输出**：每位病人一个**事件包**（格式见 `docs/event-package.md`），放在输出根目录；`_records/` 放报告、批次记录、裁定表、模型调用记录。另出便于复用的导出视图：各工序结果 xlsx、用药暴露区间表、检验长表、抽取训练样本。

## 3. 产线（插件内部的环节）

| 环节 | 对应 | 做什么 | 验收门（不通过就停在这一步，不往下游） |
|---|---|---|---|
| S01 读入·片段 | 工序1 前置 | 把原始记录切成片段，挂可见时间与依据；剔除作废记录（`INVLD_FLG=1`）；处理时间陷阱（`CRT_TM` 是迁移时间不能用、入院记录夹带补充/出院诊断要按段落拆、同次住院两版入院记录、血液净化中心按月计费的“伪住院”） | 片段数与源记录对得上 |
| S02 提及抽取 | 工序1 v1.2 | 栏目 → 句 → 分句 → 顿号拆分与修饰继承 → 过滤 → 挂发生时间（七级来源优先级、时间短语换算） | ① 原文与片段 s..e 逐字一致；区间不倒置；文书提及发生时间不晚于写成时间。三项零失败 |
| S03 类型切分 | 工序2 v2.2 | 事实／判断／决策 → 细分 → 细项；阴性、模板化、时间性质、来源、指向未来、兼含、动作、执行状态、确定程度、依从；43 条规则按优先级命中即停 | ② 兜底规则（Z2、Z9）命中率 ≤ 3%（阈值可配），超出告警 |
| S04 事件归并 | 工序3 v1.5 | 五种形态（点、片段、状态、一次性、就诊容器）；七级归并规则；概念归一词表；用药 180 天断段；生成交给矛盾判断的线索 | ③ 每条提及恰好属于一个事件；事件内类型一致；两条结构化记录不被合成一个事件 |
| S05 矛盾判断 | 工序4 v1.0 | 七类判定（矛盾、改判、调整、病情变化、命名不一致、记录质量、证据不足）；R1–R10；来源可信度六级给建议采信；换药窗口 14 天；否认上位概念表 | ④ 每条发现都能回溯到原始提及 |
| S06 人工复核 | — | 需人工确认的发现、药名映射（需药师复核）、前句继承的待定时间、兜底命中抽样 | 裁定写入裁定表，重跑沿用 |
| S07 交付 | — | 事件包＋导出视图＋报告 | 源文件只读核对一致 |

规则细节以 `docs/reference/工序1–4/设计.txt` 为准（含正则、词表、规则顺序、修订记录、待验证问题）。**不复用旧 Python 脚本**，按设计重新实现。

## 4. 模型怎么用

规则是主体。模型只处理规则判不了的四类项，并且**只给建议**：

| 环节 | 模型处理的项 |
|---|---|
| S02 | 前句继承得到的时间（标“待复核”的那些） |
| S03 | 落入兜底 Z2、Z9 的提及的类型 |
| S04 | 归不了一的概念、药名（商品名→通用名候选） |
| S05 | 需人工确认、证据不足的发现 |

- 模型结论必须引用提及编号，插件回原文核对引用；核对不上的丢弃并计数。
- 可配置两个模型：建议模型和核验模型。两者一致 → 作为规则改进候选（进“规则改进”面板，由人采纳到规则包、升版本）；两者分歧 → 进人工复核。
- 模型结论不改规则结果；采纳后通过规则包生效，结果仍可复跑。

## 6. 复用要求（这是独立成插件的理由，必须做到）

1. **不写死血透**。规则包分数据源层、通用医学层、专科层（`docs/family.md` §4.6）。不装专科包也要能跑。
2. **导出好用**：除事件包外，提供用药暴露区间表、检验长表、按句的抽取训练样本、各工序结果 xlsx（原 结果.xlsx 的样式可参考）。
3. **自带复核状态**：冲突、药名映射复核到什么程度，随事件包交付。
4. **提供 as-of 查询**：给定时刻 T，返回只用 T 以前写成的提及计算的事件与发现（评测、本体都要用）。
5. **稳定编号**（`docs/family.md` §4.3）。

## 7. Agent 工具（草案）

| 工具 | 用途 |
|---|---|
| `event_start` | 启动批次（`inputDir` / `inputs`、`outputRoot`、`resumeFrom`），立即返回 runId |
| `event_cancel` | 取消批次，已完成的部分保留在 `_records/runs/<runId>/output` |
| `event_status` | 进度、各验收门状态、待复核数 |
| `event_report` | 读 Markdown 报告 |
| `event_runs` | 列出最近批次 |

Agent 工具不能选择模型端点、模型、API Key（同匿名化插件）。

## 8. 已定口径（来自设计文档“已定口径”与讨论）

- 否认／无／予列表按顿号拆开，每条记修饰继承。
- 入院记录查体模板逐项拆，到类型切分再标模板。
- 继承来的时间是近似，提及抽取不硬修，留给复核。
- 一次性事件不看时间合并；商品名→通用名合并并标需药师复核；相关不同名诊断不合并、记候选同义。
- 模板化否认与阳性并存归记录质量；分期分级变化只记病情变化。

## 9. 待验证问题（来自设计文档）

- 处理意见里“3天后复查”这类指向未来的时间，是否单独存“计划执行时间”。
- 句内因果（“因A，暂停B”）目前不拆。
- “规律服用某药”只记一条（决策＋依从属性）。
- 症状、查体只在同一次就诊内合并，跨就诊仅逐字复制可并，漏并情况待复核。
- 引号里以空格分隔的整串诊断目前当成一个诊断名。
- 影像改判只看“同一对象、前一次带不确定措辞、发现名词改变”，可能漏掉。
- 同日多次采样（透前透后）时数值矛盾可能误报。
- 上位概念表需医生补充。
